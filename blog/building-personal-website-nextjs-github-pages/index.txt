1a:T8c73,<h1 id="building-a-personal-website-with-nextjs-and-github-pages-using-cursor-ai">Building a Personal Website with Next.js and GitHub Pages Using Cursor AI</h1>
<p><strong>Fun fact: The website you're browsing right now—including this very blog post and cover image —was created entirely with the assistance of Cursor AI.</strong> As you read through this article, you're experiencing content that was collaboratively written between a human developer (me) and an AI assistant.</p>
<p>In this post, I'll take you behind the scenes to show how Cursor AI helped me create this personal website from scratch, analyze the project structure, and overcome several technical challenges along the way.</p>
<h2 id="what-is-cursor-ai">What is Cursor AI?</h2>
<p>Before diving in, let me briefly explain what Cursor AI is. Cursor is an IDE built on VSCode that integrates powerful AI capabilities directly into your development workflow. It can help with code generation, debugging, refactoring, and even content creation like blog posts.</p>
<p>What makes Cursor particularly powerful is its ability to understand the context of your entire project. It can reference existing code, understand your coding style and preferences, and make suggestions that are consistent with the rest of your codebase.</p>
<p>Throughout this project, Cursor served as my pair programmer, helping me make architectural decisions, generate code, fix bugs, and create content—dramatically accelerating the development process.</p>
<h2 id="my-experience-pair-programming-with-cursor-ai">My Experience Pair Programming with Cursor AI</h2>
<p>As someone with a background in video compression and machine learning rather than web development, I found Cursor AI to be an invaluable partner in this project. While I had basic knowledge of React and JavaScript, building a complete Next.js website with proper deployment would have taken me significantly longer without assistance.</p>
<p>My typical workflow with Cursor looked something like this:</p>
<ol>
<li><strong>Ideation</strong>: I'd describe a feature or component I wanted to build</li>
<li><strong>Implementation</strong>: Cursor would suggest code to implement it</li>
<li><strong>Refinement</strong>: I'd review, modify, and integrate the code</li>
<li><strong>Learning</strong>: I'd ask follow-up questions to understand why certain approaches were used</li>
</ol>
<p>This collaborative approach allowed me to learn about Next.js and modern web development practices while making rapid progress on the site.</p>
<h2 id="project-overview">Project Overview</h2>
<p>This personal website serves multiple purposes:</p>
<ul>
<li>Showcase my professional background and skills</li>
<li>Display my portfolio of projects</li>

<li>Provide contact information</li>
</ul>

<li><strong>TypeScript</strong>: For type safety</li>
<li><strong>Tailwind CSS</strong>: For styling</li>
<li><strong>GitHub Pages</strong>: For hosting</li>

</ul>

<p>When I first opened Cursor to start this project, I had a simple prompt:</p>
<pre><code>I want to create a personal website using Next.js and deploy it to GitHub Pages. I'm a researcher in computer vision and video compression. What would be a good way to set this up?
</code></pre>
<p>Cursor provided detailed steps for setting up the project:</p>
<pre><code class="hljs language-bash"><span class="hljs-comment"># Create a new Next.js project with TypeScript, Tailwind CSS, and ESLint</span>
npx create-next-app@latest personal-website --typescript --tailwind --eslint

<span class="hljs-comment"># Navigate into the project directory</span>
<span class="hljs-built_in">cd</span> personal-website

<span class="hljs-comment"># Install additional dependencies for GitHub Pages deployment</span>

</code></pre>
<p>It then suggested modifying the <code>next.config.js</code> file for GitHub Pages compatibility and walked me through creating a GitHub Actions workflow for automatic deployment.</p>
<p>What impressed me was that Cursor didn't just provide commands but explained why each step was necessary and how the pieces fit together. It felt like having a senior developer guiding me through the process.</p>

<h2 id="major-challenges-and-how-we-overcame-them">Major Challenges and How We Overcame Them</h2>
<p>Throughout the development process, we encountered several significant challenges that tested our problem-solving abilities. Here are some of the most memorable ones:</p>
<h3 id="challenge-1-typescript-errors-with-third-party-libraries">Challenge 1: TypeScript Errors with Third-Party Libraries</h3>
<p>One of the first major issues arose when integrating Chart.js for the analytics dashboard. TypeScript was throwing errors because the library's type definitions didn't match how I was using it:</p>
<pre><code>Type error: Property 'responsive' does not exist on type 'ChartOptions&#x3C;"bar">'.
</code></pre>
<p>I asked Cursor for help, and it proposed a solution that involved creating custom type declarations:</p>
<pre><code class="hljs language-typescript"><span class="hljs-comment">// src/@types/chart.js/index.d.ts</span>
<span class="hljs-keyword">import</span> { <span class="hljs-title class_">ChartOptions</span> } <span class="hljs-keyword">from</span> <span class="hljs-string">'chart.js'</span>;

<span class="hljs-keyword">declare</span> <span class="hljs-variable language_">module</span> <span class="hljs-string">'chart.js'</span> {
  <span class="hljs-keyword">interface</span> <span class="hljs-title class_">ChartOptions</span>&#x3C;<span class="hljs-title class_">TType</span> <span class="hljs-keyword">extends</span> <span class="hljs-title class_">ChartType</span> = <span class="hljs-title class_">ChartType</span>> {
    <span class="hljs-attr">responsive</span>?: <span class="hljs-built_in">boolean</span>;
    <span class="hljs-attr">plugins</span>?: {
      <span class="hljs-attr">legend</span>?: {
        <span class="hljs-attr">position</span>?: <span class="hljs-string">'top'</span> | <span class="hljs-string">'left'</span> | <span class="hljs-string">'right'</span> | <span class="hljs-string">'bottom'</span> | <span class="hljs-string">'center'</span> | <span class="hljs-string">'chartArea'</span>;
      };
      <span class="hljs-attr">title</span>?: {
        <span class="hljs-attr">display</span>?: <span class="hljs-built_in">boolean</span>;
        <span class="hljs-attr">text</span>?: <span class="hljs-built_in">string</span>;
      };
    };
  }
}
</code></pre>
<p>Cursor explained, "This creates a declaration merging that extends the original types from Chart.js with the properties you need. It's a pattern often used when third-party libraries have incomplete type definitions."</p>
<p>This solution not only fixed the immediate error but taught me a valuable TypeScript pattern I've used multiple times since.</p>
<h3 id="challenge-2-markdown-processing-complexity">Challenge 2: Markdown Processing Complexity</h3>
<p>Initially, I wanted to use a simple regex approach to parse Markdown for the blog. Cursor helped implement this:</p>
<pre><code class="hljs language-typescript"><span class="hljs-comment">// Initial approach with regex</span>
<span class="hljs-keyword">const</span> formattedContent = post.<span class="hljs-property">content</span>
  .<span class="hljs-title function_">replace</span>(<span class="hljs-regexp">/^# (.*$)/gm</span>, <span class="hljs-string">'&#x3C;h1 class="text-3xl font-bold my-6">$1&#x3C;/h1>'</span>)
  .<span class="hljs-title function_">replace</span>(<span class="hljs-regexp">/^## (.*$)/gm</span>, <span class="hljs-string">'&#x3C;h2 class="text-2xl font-bold my-5">$1&#x3C;/h2>'</span>)
  <span class="hljs-comment">// More regex replacements...</span>
